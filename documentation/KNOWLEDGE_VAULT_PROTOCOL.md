# KNOWLEDGE_VAULT_PROTOCOL (v2.1)

База знаний проекта **Fastener Direct** + переиспользуемая база по фронтенд-технологиям.
Источник истины для сабагентов `vault-keeper` (пишет) и `vault-gardener` (аудит, только чтение).

> Изменения v2.1: версионирование хранилища (§12), статус `проверено` — только вручную (§1, §7),
> привязка заметки к коду (§5, §9), переработанная логика очереди и защита от повторного разбора (§4, §6).

---

## 1. Принципы

- **Двойное назначение** — подготовка к защите и постоянный справочник по технологиям. Два корня (§2), разные шаблоны (§5).
- **Чат — кратко, заметка — подробно.** Полный разбор — в файл, не в чат.
- **Учить, а не описывать.** Тема технологии даёт понимание с нуля; элемент проекта — роль в системе и обоснование.
- **Одна тема — один файл.** Имя файла = чистое имя сущности.
- **Один вызов — один новый файл.** Неразобранное идёт в очередь (§6), не в пустые файлы.
- **Связи двусторонние; мост «теория ↔ применение» обязателен** (§6).
- **Доверие через верификацию человеком.** Агент создаёт всё в статусе `черновик`. Перевод в
  `проверено` — **только ручной, никогда агентом** (§7). Факты по технологии — со ссылкой на
  реальный `источник`; не уверен — оставить пустым и пометить, **URL не выдумывать**.
- **Версионирование обязательно** (§12): правки делает LLM, поэтому нужна история и откат.

---

## 2. Два корня и таксономия

Корень хранилища: `documentation/Записи проекта/`.

```
Записи проекта/
├── 00 Главная карта.md          MOC (в корне — точка входа)
├── Настройки/                   служебное
│   ├── _Очередь разбора.md      неразобранные ссылки (§6)
│   └── _meta/                   шаблоны
├── Проект/                      существует только в Fastener Direct
│   ├── Архитектура/ Хуки/ Компоненты/ Состояние/ Роутинг/ Каталог/ Паттерны/ Решения/
└── База знаний/                 знания о технологиях, независимые от проекта
    └── React/ JavaScript/ Tailwind/ Zustand/ React Router/ Motion/ Браузерные API/
```

**Выбор корня:** только в этом репозитории (твой код/решение) → `Проект/`; понятие/API живёт
независимо (встроенный хук, концепция JS, API библиотеки) → `База знаний/`.
Кастомный `useMomentumLift` → `Проект/Хуки/`; встроенный `useEffect` → `База знаний/React/`.

**Верхний уровень закреплён** — не переименовывать, синонимы не плодить. Канонические тех-корзины:
`React`, `JavaScript`, `Tailwind`, `Zustand`, `React Router`, `Motion`, `Браузерные API`.
Бэкенд (по факту): `Fastify`, `Drizzle`, `PostgreSQL`, `Node.js`.

**Глубину растить лениво:** проверь соседей перед созданием подпапки; не заводи папку ради одной
заметки (пока мало — клади плоско в корзину); подпапка появляется при кластере ≈3+ родственных;
имя — одно русское слово, без префиксов/слешей/скобок; новую папку логируй в отчёте.
Перенос заметок безопасен: ссылки резолвятся по имени файла, не по пути.

## 3. Когда активируется

- **`vault-keeper`** — разбор по вопросу: `разбери для защиты` / `@vault-keeper`.
- **`vault-keeper`, режим очереди** — `разбери очередь`: предложить к разбору накопившееся (§6).
- **`vault-gardener`** — аудит (только чтение): `проверь базу знаний` / `@vault-gardener`.

Без триггеров база не трогается.

---

## 4. Алгоритм `vault-keeper`

Шаги 1–3 — основная сессия; 4–9 — сабагент.

1. **Краткий ответ в чат.**
2. **Сводка-заявка:** корень и папка, тип заметки (§5), режим, скелет секций, что уйдёт в очередь.
3. **Ожидание подтверждения.** Без «ок» не делегировать.
4. **Проверка существования (защита от повторного разбора).** Найти заметку по имени файла
   **и по `aliases`**. Развилка:
   - **нет** → создавать новую;
   - **есть и вопрос уже покрыт** → НЕ дублировать. В чат: «уже разобрано в [[…]]», суть в 1–2 строки,
     предложить: открыть / дополнить новым аспектом / пропустить. Без явного «дополни» — не писать;
   - **есть, но вопрос про новый аспект** → дописать дельту (§7).
5. Определить корень (§2) и тип (§5).
6. Развернуть скелет в полный разбор по шаблону. Тему технологии — учить с нуля. Не противоречить
   краткому ответу. Факты — из кода (`Read`/`Grep`/`Glob`) и реальных источников.
7. Поставить ссылки и **мост** (§6). Неразобранное — в очередь, без заглушек.
8. Создал новую заметку → **удалить её строку из `Настройки/_Очередь разбора`**, если была. Обновить `00 Главная карта`.
9. Вернуть подтверждение в чат (§10), напомнив, что статус `черновик`.

**Режим `разбери очередь`:** прочитать `Настройки/_Очередь разбора`, отсортировать по числу источников
(приоритет — больше источников выше), показать топ, спросить — разобрать одну тему или пакет.
Дальше по обычному циклу (со сводкой и подтверждением), снимая разобранное из очереди.

## 5. Три типа заметок (шаблоны в `Настройки/_meta/`)

- **Элемент проекта** → `Проект/`. Дополнительно frontmatter `код:` — путь(и) к файлу исходника,
  который заметка описывает (для проверки актуальности садовником, §9).
- **Тема технологии** → `База знаний/`. Поле `источники` обязательно (реальные ссылки).
- **Решение / ADR** → `Проект/Решения/`.

Все создаются со `статус: черновик`. **Агент `проверено` не ставит никогда.**

Обучающие блоки: «Проверь себя» — во всех; «Вероятные вопросы на защите» — в проекте и решениях;
```mermaid — для структурных тем.

---

## 6. Связи и очередь

- Ссылки `[[…]]` ставятся в тексте. **Файлы-заглушки не создавать** — Obsidian держит неразрешённые
  ссылки и беклинки сам.
- **Мост (обязателен):** заметка `Проект/` → раздел «Стоит на» + `теория` во frontmatter; в
  существующую тех-заметку — обратная связь «Где встречается в проекте» + `встречается-в`.

**Логика `Настройки/_Очередь разбора` (важно):**
- **Дедуп с накоплением.** Перед добавлением проверить, есть ли строка с этой ссылкой. Есть →
  не плодить дубль, а **дописать источник** в скобки. Число источников = приоритет.
  `- [[Замыкания]] → База знаний/JavaScript/ (из: [[useEffect]], [[useMomentumLift]])`
- **Снятие при разборе.** Создана заметка темы → её строка из очереди **удаляется** (§4 шаг 8).
- Разбор очереди — через режим `разбери очередь` (§4), по приоритету.

---

## 7. Append и статус

- Заметка есть → добавить **только новое**, без повторов; строка в «Журнал изменений»
  `- YYYY-MM-DD — <что> (вопрос: «…»)`; обновить `обновлено:`. **Статус остаётся `черновик`** —
  агент его не меняет.
- Заметки нет → создать по шаблону (`статус: черновик`), связи, мост, в карту, снять из очереди.
- **Перевод в `проверено` — ручной, делает пользователь** после того, как сверил факты и ответил
  на блок «Проверь себя» этой заметки. Это единое действие: верификация факта + проверка понимания.

---

## 8. Именование и язык

Сущность/API → английское имя как в коде (`useEffect.md`). Понятие с русским термином → русский
(`Замыкания.md`). Без дублирующих префиксов. `aliases` — рус + англ (поиск/ссылки ловят оба).
Текст русский; английский — имена сущностей, классы Tailwind, код; один вариант для понятий
(«состояния», не «state/стейт»). Пути с пробелами/кириллицей в bash — в кавычках.

## 9. `vault-gardener` — аудит (только чтение)

Ничего не пишет; выдаёт отчёт и рекомендации, правки — отдельным подтверждённым шагом. Проверяет:
1. Дубли/синонимы папок.
2. Папки-одиночки.
3. Кластеры в очереди (≥3 источника) — пора разобрать.
4. Застрявшие — `черновик` и пометки `(требует проверки)`.
5. Битый мост — `Проект/` без «Стоит на»; `База знаний/` без «Где встречается».
6. Осиротевшие заметки.
7. **Привязка к коду** — для заметок `Проект/` с полем `код:`: файл существует? менялся ли позже
   даты `обновлено`? → подсветить устаревшие (эвристика, для ручной перепроверки).
8. **Незакоммиченное** — `git status` в хранилище: если есть несохранённые правки, напомнить закоммитить.

---

## 10. Output contract (`vault-keeper` → чат)

2–5 строк: путь · тип · создано/дописано · мост · сколько ушло в очередь · что `(требует проверки)`.
Напомнить: статус `черновик` — перевести в `проверено` вручную после самопроверки. Разбор в чат не пересказывать.

---

## 11. Антипаттерны

- Разбор в чат вместо заметки; запись до подтверждения; дублирование при забытом прошлом разборе (§4).
- **Агент ставит `проверено`** — запрещено. **Выдуманный `источник`/URL** — запрещено.
- Прогон технологии через проектный шаблон; склейка сущностей; дубли при append.
- Файлы-заглушки; пустые подпапки; синонимы категорий верхнего уровня.
- Оставлять в очереди разобранную тему; плодить дубль строки вместо накопления источников.
- Заметка проекта без моста к теории / тема технологии без обратного моста.

---

## 12. Версионирование хранилища

Хранилище игнорируется основным репозиторием проекта (чтобы правки заметок не засоряли историю кода),
но **ведётся как собственный независимый git-репозиторий** — это даёт бэкап, историю и откат
неудачных правок агента.

- Внутри `documentation/Записи проекта/` — отдельный `git init`, свои коммиты, по желанию приватный remote.
- Основной репозиторий продолжает игнорировать эту папку (вложенный репозиторий его не касается).
- Коммитить регулярно; садовник напоминает о несохранённых правках (§9, п.8).
- Альтернатива — Obsidian Sync (бэкап и история без git).
